# NEXT11VEN — Premium Triggers & Feature Criticality Map

Every premium gate and core business surface, ranked by what breaking it would actually cost. This is the doc you check before any upgrade, and the seed list for future E2E tests.

**How to use this file**
- P0 = breaking this loses money or trust immediately (payment/access mismatch, data leak, core loop down). Test before every deploy that touches it.
- P1 = breaking this degrades growth/retention but isn't an emergency.
- P2 = nice-to-have surfaces; regressions are annoying, not urgent.
- Update "Test coverage" honestly — "None" is a valid, useful answer that tells you where to start.

**Columns**
- **Trigger/Feature**, **Type** (paywall gate / core flow / automation), **Criticality** (P0/P1/P2), **What it protects**, **Test coverage**, **Code location**, **Known edge cases**

**Current automated test coverage overall (28 Aug 2026):** `vitest run` (`npm test`), 5 unit-test files total — `lib/activityRecency.test.ts`, `lib/publicStats.test.ts`, `lib/stripeSync.test.ts`, `lib/matchDay.test.ts`, `lib/shareCard.test.ts`. No E2E/integration framework installed (no Playwright/Cypress). None of the 5 files exercise an API route directly — they test pure functions extracted into `lib/`. So unless a row below says otherwise, "Test coverage: None" means literally zero automated coverage of that route/flow, not "some coverage we haven't logged."

## P0 — Revenue & access integrity

| Trigger/Feature | Type | What it protects | Test coverage | Code location | Known edge cases |
|---|---|---|---|---|---|
| Stripe webhook → premium flag sync | Automation | Correct billing state everywhere | Partial — `needsStripeSync()` recheck-window logic is unit tested (`lib/stripeSync.test.ts`); the webhook handler itself (`/api/stripe/webhook`) and the login-time sync route have no test coverage | `app/api/stripe/webhook/route.ts` (primary — flips `premium` on `profiles`, writes `subscriptions`, upserts `player_message_quota`), `app/api/stripe/sync/route.ts` (login-time catch-up sync, gated by `needsStripeSync()`/`stripe_synced_at`, `lib/stripeSync.ts`), `app/api/admin/stripe-reconcile` (manual fix tool) | Race conditions on rapid upgrade/downgrade; recheck gated to `STRIPE_SYNC_RECHECK_DAYS` so a stale local state can persist for up to that many days between logins |
| "Actively Looking" toggle (premium-only) | Paywall gate | Core player upsell hook | None | `app/api/player/actively-looking/route.ts` — `PATCH` (toggle, 403 `NOT_PREMIUM` for non-premium) + `GET` (returns `{ actively_looking, liveCount }` for the paywall copy) | Server-side enforcement confirmed (route rejects `true` for non-premium regardless of client payload) — not auto-enabled on upgrade, player must opt in each time |
| Coach Pro dashboard access (recruit-by-stats search) | Paywall gate | Coach Pro revenue line | None | `app/api/coach/performance-search/route.ts`, `app/dashboard/coach/performance/page.tsx` | The **route/page** is reachable by every coach (no redirect/404) — but the searchable dataset itself is gated: non-premium coaches get `{ locked: true }` plus a curated teaser (≤2 real players with pedigree, backfilled with non-local players so it's never empty, `nearby: false` on backfilled cards). Don't read "access stays free" as "the data stays free" — only the page shell does |
| Message coaches first / respond to messages (player premium gate) | Paywall gate | Player premium core value prop | None | `app/api/messages/send/route.ts` (send/reply gate — player sends 403 `NOT_PREMIUM`, replies included, admin exempt), `app/api/messages/initiate/route.ts` (the only path to a *new* conversation — premium + quota gated via `initiate_coach_conversation` RPC) | ⚠️ RLS enforces the READ gate only (migration `20260628000000` leaves INSERT open deliberately) — the send/reply gate lives in the API route, not the database. Don't assume RLS is backstopping this one |
| `conversations` column-level SELECT grants (message-preview paywall backstop) | Security | Prevents non-premium players reading message bodies straight off PostgREST, bypassing the read paywall | None | Migration `20260812000003` (explicit column grant list, no blanket table grant) + `conversation_previews()` security-definer RPC (enforces the actual premium check on body reads) | Any new column added to `conversations` is NOT readable by clients until explicitly granted (`grant select (new_column) on public.conversations to anon, authenticated;`) — silent failure mode is a PostgREST 403 and a broken inbox, not a security hole, but skipping this step on `last_message_content`-like columns IS a paywall bypass. Never re-add a blanket table grant here |
| RLS on `profiles` / own-row-only policies | Security | User PII | Confirmed post-incident (26 Aug 2026) — verified anon reads 0 rows, logged-in member reads exactly 1 row (own), down from 956 | Migrations `20260825000002` through `20260826000001` (six total); full write-up `docs/incidents/2026-08-25-profiles-data-exposure.md` | ⚠️ Policies were originally created in the Supabase **dashboard**, not a migration — `grep` finds nothing; query `pg_policies` directly. Standing rule: test as anon after ANY grant/policy change (`privileges sum, they never subtract` — see CLAUDE.md). One known-harmless leftover: the redundant "Users can update own profile" policy is still live (Known Gap #2 in CLAUDE.md), fully subsumed by the upsert policy |

## P1 — Growth & retention surfaces

| Trigger/Feature | Type | What it protects | Test coverage | Code location | Known edge cases |
|---|---|---|---|---|---|
| Applying to an opportunity | Core flow | Marketplace liquidity | None | `app/api/applications/apply/route.ts` (premium-gated, fires `sendApplicationReceivedEmail`) | Players apply to any role; coaches apply only to `opportunity_type='coach'` roles (not their own). Rate-limited 10/min |
| Opportunity feed | Core flow | Player daily-use loop | None | `app/api/opportunities/feed/route.ts` | Server-side gating, not visual blur: `club` is `null` in the payload for non-premium players (never sent, not just hidden client-side); `matchPercent` (60–99, `lib/opportunityRelevance.ts`) is computed and present ONLY for premium, absent entirely from the free payload. Separately, club crest chips were removed from **every** opportunity card for **all** tiers as an unrelated UI simplification — don't conflate the two facts. Single bounded fetch (limit 200), no server-side pagination yet |
| Standout carousel (Actively Looking surfacing) | Core flow | Premium conversion driver (FOMO) | None | `ActiveUserCard` in `app/dashboard/player/page.tsx` and `app/dashboard/coach/page.tsx` (Recently Active carousel, both homepages) | Green ring/glow is availability-only: `isLooking = !isCoach && user.actively_looking` — coaches never get it, a player only while the toggle is genuinely on (server-side requires premium) |
| Coach shortlisting | Core flow (ungated) | Fires player conversion trigger | None | `app/api/coach/shortlist/route.ts` (+ `[player_id]` for delete) | Intentionally free for coaches — don't accidentally gate. Fires `shortlisted` in-app notification to the player + `sendShortlistAvailableEmail` (capped 1 per coach per player per week) |
| Coach recommendation engine (weekly digest) | Automation | Coach engagement | None | `lib/recommendations.ts`, `app/api/coach/recommendations/route.ts` (on-demand), `app/api/cron/coach-recommendations` (Tuesday 08:00 UTC cron, `sendCoachRecommendationsEmail`), `coach_recommendation_log` table (migration `20260610000001_coach_recommendations.sql`) | 6-week rotation rule (a player shouldn't be recommended to the same coach every single week) must hold — enforced via `coach_recommendation_log` |
| Performance Tracker (kill switch + free-launch flag) | Paywall gate (currently disabled) | Retention + future upsell | Some domain logic covered indirectly via `lib/matchDay.test.ts` (match-day suggestion logic used by the log-nudge cron); the tracker CRUD routes themselves have no test coverage | `lib/performance.ts` — two independent env flags: `performanceTrackerEnabled()` (`NEXT_PUBLIC_PERFORMANCE_TRACKER_ENABLED`, global kill switch — API routes 404 when off) and `performanceTrackerFree()` (`NEXT_PUBLIC_PERFORMANCE_TRACKER_FREE`, free-launch mode that skips the premium gate entirely). Both are currently **`true`** in `.env.local` (confirmed 28 Aug 2026) — the whole tracker, including logging games, is free right now, not just "read" | This is deliberate per the coach-dashboard-supply-constraint finding (3 Aug 2026): match-logging volume is the platform's actual bottleneck, so charging for it now would suppress the very data the recruitment search depends on. Flipping `PERFORMANCE_TRACKER_FREE` to `false` re-enables the premium gate with no code changes — treat that flag as a live monetization lever, not a leftover |

## Notes for future E2E test planning

- Start P0 rows first — these are your minimum viable regression suite. As of 28 Aug 2026, **every P0 row has zero direct test coverage** except the Stripe recheck-window logic — this is the actual current risk surface, not a hypothetical one.
- Each P0 row eventually becomes: one "happy path" test + one "premium/free boundary" test (does a free user actually get blocked server-side).
- The security incident (25–26 Aug) is a good template for what a P0 test should have caught — direct anon-key access bypassing app-layer gating. The `conversations` column-grant row above is the same failure shape (privileges sum, not subtract) applied to messaging instead of profiles — worth a regression test for the same reason.
